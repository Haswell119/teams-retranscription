  * No ServiceMonitor: monitoring.coreos.com/v1 is absent (this is normal on
    NKP Starter, where kube-prometheus-stack is a Pro+ entitlement). Metrics are
    still exposed on the orchestrator at /metrics and on workers at :{{ .Values.worker.metricsPort }}/metrics.
{{ end -}}
{{ if not (include "hansard.capabilities.prometheusRule" .) -}}
  * No PrometheusRule: same reason. The alert definitions live in
    deploy/helm/hansard/templates/prometheusrule.yaml if you run Prometheus elsewhere.
{{ end -}}
{{ if not (include "hansard.capabilities.grafanaDashboard" .) -}}
  * No Grafana dashboard ConfigMap. Import deploy/helm/hansard/dashboards/hansard.json by hand.
{{ end -}}
{{ if not (include "hansard.capabilities.keda" .) -}}
  * No KEDA ScaledObject: keda.sh/v1alpha1 is absent.
{{ if .Values.worker.autoscaling.hpa.enabled -}}
    Falling back to a CPU HorizontalPodAutoscaler.
{{- else -}}
    Workers run at fixed replica counts. Set worker.autoscaling.hpa.enabled=true
    for CPU-based scaling, or install KEDA for queue-depth scaling.
{{- end }}
{{ end -}}
{{ if not (include "hansard.capabilities.cilium" .) -}}
  * No CiliumNetworkPolicy: cilium.io/v2 is absent, so only the portable
    CIDR-based NetworkPolicy applies. Remember that several Teams endpoints are
    published as FQDNs with no IP ranges, so a pure CIDR allowlist is incomplete
    - see docs/deployment-nkp.md.
{{ end -}}
{{ if not (include "hansard.capabilities.externalSecret" .) -}}

  * No ExternalSecret: external-secrets.io is absent (Pro+ on NKP). Secrets come
    from the in-chart Secret; move them to secrets.existingSecret for production.
{{ end -}}
{{ end -}}

THINGS TO CHECK BEFORE PRODUCTION

{{ if .Values.secrets.create -}}
  ! secrets.create=true puts credentials in Helm release data. Switch to
    secrets.existingSecret or secrets.externalSecret.
{{ end -}}
{{ if not .Values.global.requireImageDigests -}}
  ! Images are pinned by tag, not digest. Run `make -C deploy/docker digests`
    and set images.<name>.digest, then global.requireImageDigests=true.
{{ end -}}
{{ if eq .Values.networkPolicy.egress.mode "open" -}}
  ! networkPolicy.egress.mode=open allows the whole internet minus RFC1918.
    Evaluation only.
{{ end -}}
{{ if not .Values.networkPolicy.enabled -}}
  ! networkPolicy.enabled=false: there is no egress control at all.
{{ end -}}
{{ if and (eq .Values.storage.backend "filesystem") (not .Values.orchestrator.persistence.enabled) -}}
  ! Artifacts are written to an emptyDir and vanish with the pod. Set
    orchestrator.persistence.enabled=true or storage.backend=s3.
{{ end -}}
{{ if .Values.webhook.enabled -}}
  ! webhook.enabled=true requires a PUBLIC inbound HTTPS endpoint that answers
    the Microsoft Graph validation handshake in under 10 s. This is incompatible
    with an air gap; polling is the sovereign default.
{{ end -}}
{{ if and .Values.minutes.enabled (not .Values.minutes.endpoint) -}}
  ! minutes.enabled=true but minutes.endpoint is empty, so summarisation is off.
    Point it at an OpenAI-compatible endpoint you host yourself.
{{ end -}}

Sovereignty check: no telemetry is emitted, no model is downloaded at runtime
(HF_HUB_OFFLINE=1, HANSARD_RUNTIME__ALLOW_MODEL_DOWNLOADS=false), and the only
egress permitted is what you configured under networkPolicy.egress.
